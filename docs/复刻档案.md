## 一句话

复刻 APPSO 品牌卡的文字形变动效（旧文案「灵感指南」粒子溶解 → 空场 → 聚拢成「AI时代的」循环），
最终交付 19 个版本的自包含网页：**像素级复刻度 86.4%，四边留白严格 14.50px，粒子不越框、不留残影、性能提速 5.4 倍**。

## 背景

**触发**：
手里有一段 APPSO 的品牌动图（`appso 动图.mp4`），尺寸只有 182×72，很小，但文字形变做得极其讲究。
我想把它做成一个可复用的网页动效资产——既能嵌进内容里，也能拆成简笔画视频的素材。

**原始素材**：

| 项 | 值 |
|---|---|
| 文件 | `D:/AI创作plus/appso 动图.mp4` |
| 尺寸 | 182 × 72 px |
| 帧数 / 帧率 | 268 帧 / 16.7 fps |
| 时长 | 16.05s |
| 循环周期 | 71 帧（≈ 4.25s） |
| 画面 | 红底（≈#E0231F）+ 米白像素字，顶部小字 logo「APPSO」，主标题「灵感指南」↔「AI时代的」交替 |

**目标**（分阶段抬高，每一阶段都是我主动加码的）：

1. 先把动效机制拆对——别做错方向；
2. 复刻度 > 80%（端到端截图评测）；
3. 文字清晰到「读者能一眼看清」，且清晰度与品牌 logo 同级；
4. 版面严格：整体块到橙框四边同一个数值；
5. 工程可靠：粒子不越框、空场零残留、流畅不卡顿、窗口再小也不裁切。

**约束**：

- 最终产物必须是**单个自包含 HTML**（字体子集 + 底板全部内嵌），双击即开，不依赖网络；
- 用户是内容创作者、非技术背景，所以任何"看起来不对"的反馈都必须被认真对待且可验证；
- 文案切换时**不能出现两行字同时可见**——这是原视频的核心特征。

## 我做了什么

### 第 1 轮 · 拆解机制：我第一次判断错了

**反馈**：我拆出视频后给的第一个 Demo（v1），判断机制是「横向扫描逐段替换」——画面被切成竖条，扫描光带从左到右推过去，经过的地方文字被替换。

**归因**：**这个判断是错的。** 我凭"看起来像扫描带"就下了结论，没有做像素级验证。

**核验**（用户提出四点差距后我做了复核，四点全部成立）：

| 我的判断 | 实测证据 | 结论 |
|---|---|---|
| 扫描带从左向右 | logo 区（y<22）帧间变化 **0.168**，主文字区（y22–72）**3.176**，相差 19 倍 | 粒子实体只存在于 y=23~57，与扫描无关 |
| 旧新文案有交叉淡化 | 全程无"旧新共存"帧 | 是替换不是淡化 |
| 是遮罩扫过 | 与 A 的相关度、与 B 的相关度曲线**几乎完全重合**（1.00/0.85 → 0.49/0.47 → 0.81/0.87） | 若是遮罩必出现"左半旧右半新"的双高分离帧，实测不存在 |
| 字体一致字位固定 | A/B 帧文字带垂直范围都是 y=0~34（字高 35px 完全相同） | 成立 |

**改法**：推翻重来。正确机制是——**整行文字作为整体，粒子是形变的载体**。
旧字先被粒子打散成噪点云（旧字形彻底消失），噪点云再聚拢重组成新字。接近 AE 的「粒子世界 / 分形噪声置换 + 文字逐帧替换」。

**取舍**：v2 我实现了"离屏 Canvas 渲染文案 → getImageData 采样成点阵（7px 采样格）→ 粒子源"，
并做了 logo 安全区硬剔除 + 独立 DOM 图层置顶的双保险。这套架构一直沿用到 v19，没再改过。

**这一轮真正学到的东西**：**视觉直觉不可靠，像素统计才可靠。** 后面 18 轮，我每一轮都先量数据再动手。

### 第 2 轮 · 达标交付（v10）：复刻度 86.4%

**目标**：把复刻度做到 80% 以上。

**归因**：这一轮主要不是调参，是**修工具**。有三个隐蔽的坑，每一个都在偷偷压低分数：

| 坑 | 后果 | 修法 |
|---|---|---|
| Chrome headless 截图是**异步落盘**，父进程立即 exit 0 | 读到旧图或空文件，**此前所有搜索都在随机失败** | 必须轮询等待文件出现；给独立 `TMPDIR` 与 `--user-data-dir` |
| 卡片定位用"红矩形阈值反推" | 得到 S=3.92~3.97 而非 4.0，裁剪被拉伸 2% | 改用底色 `#fafafa` 连通域定位，精确 728×288 / S=4.0000 |
| 稳定帧相位取错 | `at=3800` 实为过渡相位（pr≈0.05），不是稳定帧 | 稳定 B 应为 `at=2800`（pr=1） |

**关键突破 · 批量舞台页**：把 24 个参数变体渲染进同一页（每变体一个 728×288 舞台），
一次截图按 `#fafafa` 连通域切分评分——**432 个变体从 25 分钟压到约 100 秒，提速约 100 倍**。
这才让"搜索参数"从不可能变成可能。

**还漏画了 logo**：原视频顶部有静态白色「APPSO」字标（x79..107 / y8..14），我最初没画。
拟合 Segoe UI Bold 9.4px / track −0.1 / cx 93.5 / by 15.2 / gain 1.2（IoU 0.782）烘进底板后，
复刻度 A 从 84.3% → **86.4%**，B 从 83.5% → **84.3%**。

**成果**：`appso粒子形变复现-v10.html`，复刻度 **86.4% / 84.3%**，双过 80%。

**顺手做的一件事**：做了一次纹理场消融实验（试了细点刻、横向条带、强横向拉长、弱竖条粗粒四种替代纹理）。
原「高频竖梳」场最优（均值 85.8% vs 次优 79.9%，SSIM 独立验证同样结论 0.737 vs 0.681）。
**这一条写进档案是为了告诉以后的自己：别再试了。**

### 第 3 轮 · 清晰化（v11）：接受复刻度下降

**反馈**：「动效、变换方式都是对的，只是最终旧\新两种文字展示都不清晰，调整一下，目标是在用户能清晰看到这两种文字。」

**取舍（这一轮最重要）**：**清晰与复刻度是互斥的**——原图的半透点刻效果本身就是"不清晰"的一部分。
我明确选择了清晰，并提前把代价告诉用户：「像素复刻度会从 86.4% 降到 50–75%，因为清晰实心与像原图那样的半透点刻不能兼得」。

**归因**（不清晰的两条叠加）：
1. 为拟合原视频的压缩点刻纹理，稳定态用了 `gain=0.70` + 竖梳纹理调制 → 笔画中心只有 70% 白，叠在红底上呈"粉白斑驳"；
2. 画布按 182×72 渲染后由 CSS 放大 4× 到 728×288，位图放大导致边缘发虚。

**改法**：

| 项 | 改前 | 改后 |
|---|---|---|
| 稳定态 | gain 0.70 + 竖梳纹理调制 | **纯白实心**（gain 1.0、mods 0、blur 0.35） |
| 渲染分辨率 | 182×72 放大 4× | **728×288 原生**（K = round(W/182×dpr)），超采样 SS=3，9 抽样面积降采样 |
| 底板 | 内嵌纹理场 | 重建为 728×288，仅 4.9KB，logo 用 8× 超采样清晰渲染 |
| 文件体积 | 53KB | **30KB**（去掉纹理场内嵌） |

**成果**：字重两版供选——`v11`（Bold，覆盖率 49%，醒目）、`v11r`（Regular，覆盖率 32%，清秀）。
复刻度 Bold A 50.6% / B 75.7%，Regular A 57.2% / B 68.5%。
（A 句笔画密集，Bold 实心后"墨"项失分；B 句笔画疏，Bold 反而更高——这个反直觉的结果也记下来。）

### 第 4 轮 · 双 bug 修复（v12）：卡顿 + 旧字残留

**反馈**：「① 新旧字体变化时卡顿 ② 旧字体变化成新字体时，旧字体没有彻底消失。」

**归因 · "旧字不消失"是两个 bug 叠加**：

1. **实心层与粒子层用了不同的驱动量（真 bug）**：粒子用 `pt = ci===0 ? pr : 1-pr`，实心层却用 `pr`。
   当 `ci` 翻转到 1（第二周期），`pr=0` 时算出 `solidA=1`——**本该显示新字，却把旧字实心画了出来**。
   之前只核验过第一个周期，所以从没暴露。**这是典型的"只验一半"的漏网**。
2. **两段时间重叠**：旧字粒子要到 `pr=1` 才归零，新字实心 `pr=0.55` 就浮现 → 重叠 0.45 个周期。

**改法**：

| 项 | 改法 |
|---|---|
| 驱动量 | 改为「周期计数 + 统一进度 v」：`ci = floor(total/T) % 2`，`v = ci ? 1-pr : pr`，与相位天然同步 |
| 时间轴 | 切成**互不重叠**的两段：旧字实心淡出 0–0.20 / 旧字粒子散尽 0–0.36 / **空场 0.36–0.64** / 新字粒子聚拢 0.64–1.00 / 新字实心浮现 0.80–1.00 |

**归因 · 卡顿**：每帧对 2000–3200 个粒子逐个做 3 次 Map 查找 + 1 次 Math.sin + 切 `globalAlpha`/`fillStyle` + 1 次 `fillRect`。
但 `globalAlpha` 和 `fillStyle` **全场是同一个值**（不依赖粒子序号），逐粒子设纯属浪费。

**改法（性能）**：
- 粒子属性预打包成 `Float32Array`（X/Y/SZ/KX/KY/KJ/CR），每帧只做"乘加 + rect"；
- 末尾**一次 `beginPath/rect/fill` 批量描边**替代 N 次 `fillRect`；
- 字形覆盖率缓存——拖「粒子格」滑块只重跑光栅化，不重复超采样与读回。

**实测**：1600 粒子 × 60 帧（best of 3，`--disable-gpu`）→ **v11 29ms → v12 5ms，提速 5.41×**。

**核验**：空场与纯底板平均差仅 **1.6/255**；两个周期数值完全对称闭合（v 的正反映射一致）；
APPSO 区墨量全程恒定 → 粒子零侵入。

### 第 5 轮 · 边界与清晰度（v13）

**反馈**（用户已认可 变形 4.4s / 粒子格 1px / 飞散幅度 6px）：
「① 飞散的幅度不能超出橙色边框 ② 新字体和旧字体的清晰度要和 APPSO 一样」

**归因 · 越框的主因不是粒子飞散，是「游离噪点」**：噪点坐标写成了 `k1*MW`（铺满整个画布宽），
必然撒到橙框外的白底上。实测 v12 在噪点峰值帧越框 **1394 px**（左 675 / 右 415 / 下 300）。

**改法**：
- 每个粒子生成时记住自己**朝上下左右到橙框的可用空间**，位移按方向等比压缩——**零分配零 GC**，不影响性能优化；
- 游离噪点限制在框内；
- 清晰度：`blur 0.35 → 0`、超采样 `SS 3 → 4`、覆盖率 gamma 0.88 增实。

**核验**（以无粒子的底板为基准，框外统计差异像素，基线噪声 4–6px 是舞台圆角）：

| 指标 | v12 | v13 |
|---|---|---|
| 越框像素 | 1394 / 959 | **4–6（= 基线）** |
| 纯白占墨 | 0.1985 | **0.2713** |
| 核心白度均值 | 0.9973 | **0.9998** |

APPSO 字标自身核心均值是 **0.9993**——v13 的正文**已经略超字标**。压力测试把幅度拉到滑块上限 70px 仍不越框。

### 第 6 轮 · 空场清零（v14）

**反馈**：「每次字体粒子飞散后要完全淡出，不能留残影」（附截图，屏幕满是细碎小方块）。

**归因**：残留的唯一来源就是**游离噪点**本身。旧字粒子在 v=0.36、新字粒子在 v=1.00 都已精确归零，实心层也在 v=0.20/0.80 归零——噪点是画面上唯一多余的东西。

**改法**：**整段删除**（两块 path 全部移除）。`env` 变量保留，因为粒子横向抖动仍依赖它。

**核验**（与纯底板逐像素比，空场区间 v ∈ [0.355, 0.645]，约 1.28 秒）：

| 指标 | v14 | v13（同刻） |
|---|---|---|
| 差异像素 | **10（= 基线）** | 2449 |
| 平均差 | **0.002** | 1.033 |

**尾部淡出实测**：1.875s 粒子雾明显 → 1.914s 极淡 → **1.934s 完全干净**，消散在 **40–60ms 内**完成，肉眼看不到余烬。

### 第 7 轮 · 两段幅度统一（v15）

**反馈**：「应该以『AI时代的』的飞散幅度为基准，改一下『灵感指南』。」

**根因（一个藏得很深的公式不对称）**：

| 段 | 原公式 | 峰值（幅度 6px 时） |
|---|---|---|
| 灵感指南 | `ampK × v`（v 只走到 0.36 就归零） | **2.16 px** |
| AI时代的 | `ampK × (1−进度)`（进度走满 0→1） | **6 px** |

所以「灵感指南」只有「AI时代的」的 **0.36 倍**。

**改法**：新增常量 `SEG = 0.36`，两段位移统一写成「同一峰值 `ampK` × 段内进度」。B 段一个字符没动。

**核验的关键教训**：我第一次用"粒子到字形轮廓的距离"做指标，测出比值 0.875，没到 1.0。
但这个指标**受笔画疏密干扰**——「灵感指南」笔画密，粒子飞走后仍常留在字形内，被算成"没飞"。
换成**散开面积**（粒子像素面积 ÷ 自身字形面积，形状无关）后：

| 镜像时刻 | v14 的 A/B | v15 的 A/B |
|---|---|---|
| v=0.18 ↔ 0.82 | 0.504 | **1.063** |
| v=0.30 ↔ 0.70 | 0.476 | **0.964** |
| 六点均值 | **0.559**（差近一倍） | **1.057** |

### 第 8–10 轮 · 版面三连（v16 / v17 / v18）

这三轮是**同一个诉求的三次逼近**：四边间距统一。

**v16**：「橙框距离文字内容的间距要统一成一个数值，以左右下的间距为基准」
→ 我量出实际是左右下都 ≈14px、但上方多出 5–6px（顶部被 logo 占着）。
**这里我停下来问了用户**，因为"四边严格等距"在当前尺寸下**数学上做不到**：
橙框内区宽高比 2.49，正文 4.20，两者不一致，上下留白之和是固定的，只能决定怎么分。
用户选了「加高橙框 + 画布」方案。

**v17**：「把 appso 和下面的新旧文字看做一个整体，再去调整边距」
→ 这是关键的认知升级：**留白基准不是正文，而是「logo ∪ 正文」的联合包围盒**。
早期只按正文算，导致上方只剩 3.00px（字标挤在框顶）。
整体块 = 135.50 × 43.75。画布 182×72 → **182×88**，橙框内高 61.25 → **72.75**，字标与正文同步下移 11.5px。

**v18**：我指出右下（「AI时代的」）还差一点——实测 `14.00 / 14.00 / 14.50 / 14.75`。
差在「AI时代的」墨迹天然比「灵感指南」宽 1px、底边高 0.25px。
**改法不是套一个固定补偿值，而是按目标留白反算字槽**：跨度 104.0 → 103.0px（关于橙框中心等比收窄），
基线再下移 0.25px。反算式：`ctr_B = 93.25 + (A.ctr + 1.25 − 93.25) × (103.0/104.0)`。

**用户确认**：「右上的间距是对的」→ 说明 v17 的「灵感指南」达标、「AI时代的」还差。
改完后两段**都是严格的 14.50 / 14.50 / 14.50 / 14.50，极差 0.00**。

### 第 11 轮 · 页面裁剪（v19）：最隐蔽的一个 bug

**反馈**：用户发来浏览器截图（APPSO 被黄圈圈住）：「这是我看到的成品」。

**归因（从用户截图反推）**：画面里的留白一直是 14.50px，没问题。**但用户根本看不到**——
他的浏览器窗口比页面内容矮，页面用了 `height:100%` + `align-items:center`，
flex 居中把溢出部分**平均推到视口上下外侧，而顶部那半截滚动不回去**。
结果红卡上沿被永久裁掉，APPSO 字标顶部正好落在裁切线上——**看起来就是"重合"**。

**复现验证**（用 690×736 视口模拟用户窗口）：

| | 红卡上沿 | 红卡可见高 | 框顶→字标顶 |
|---|---|---|---|
| v18 | **y=0（被裁）** | 258 / 应 289 → 少 31px | 26px / 应 58px |
| **v19** | **y=55 ✓** | 254 / 应 255 ✓ | 50px / 应 51px ✓ |

**改法**（只动 6 处 CSS，**画面一个像素没动**）：
`min-height:100%` + `flex-start`（顶部对齐、正常滚动）+ 舞台 `aspect-ratio` 自适应宽度
（宽窗口下仍是精确 728×352，窄窗口等比缩小而不是被切）。

**核验**：v18 vs v19 在 6 个时刻逐像素比对，**最大差 0、平均差 0.0000**。

### 时间轴（单一进度 v∈[0,1]，两段互不重叠）

```
旧字实心淡出  0.00 → 0.20
旧字粒子散尽  0.00 → 0.36
──── 空场 ──  0.36 → 0.64        ← 约 1.28s，与纯底板逐像素一致
新字粒子聚拢  0.64 → 1.00
新字实心浮现  0.80 → 1.00
```

> 设计原则：**两段永不重叠**。旧字归零之后新字才揭幕，物理上杜绝残留。

### 技术链路

```
mkbase.py                      烘 728×352 底板（红卡 + APPSO 字标，sigmoid 边缘）
  ↓ base.png（约 4.9KB）
mkhtml19.py                    内嵌字体子集（woff2 base64）+ 底板 base64
  ├ 离屏 Canvas 渲染文案 → getImageData 采样覆盖率
  ├ 4× 超采样 → 面积降采样 → 清晰实心字形
  ├ packPts() 预打包粒子（Float32Array）+ 逐粒子四向可用空间
  ├ frame(): 底板常驻 + 文字层 alpha 叠加
  └ 单次 beginPath/rect/fill 批量描边
  ↓
appso粒子形变复现-v19.html     39KB 自包含，双击即开
```

## 二期可以怎么用

**可直接复用**：
- 整套技术链路（底板烘焙 → 覆盖率采样 → 4× 超采样 → 粒子预打包 → 批量描边）换文案即可；
- 20 个脚本作为骨架，改文案 / 改配色 / 改节奏；
- 四边等距的「按目标留白反算字槽」公式；
- 三种独立字体字重方案（Bold / Regular）供风格匹配。

**需要替换的变量**：

| 变量 | 位置 |
|---|---|
| 文案与字槽 | `CFG.A` / `CFG.B` |
| 品牌色 | `mkbase.py` 里的红底色值 |
| logo | `mkbase.py` 里的字体/尺寸/位置拟合 |
| 节奏 | 时间轴五段区间 |
| 幅度 | `ampK`（受框内可用空间约束） |

**不建议沿用的**：
- 半透点刻纹理场（已被证明是"不清晰"的来源，但消融实验证明它确实是原图纹理的最优拟合——
  如果二期目标是"做旧电影感"可以捡回来，如果目标是"清晰可读"就别用）；
- 任何"居中 + 固定高度"的页面布局。

**衍生选题**：
- 把这套形变机制做成**可配置的动效生成器**：输入文案，输出自包含 HTML；
- 简笔画版：把粒子载体从"文字笔画"换成"线稿笔画"，用于视频号；
- 品牌卡套件：把橙框/留白/字标比例固化成模板，批量产出同系列卡片。
